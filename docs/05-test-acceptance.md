# TradeOrbit 测试与验收方案

日期 2026-10-30 / 本文件是待执行计划，文档编制不等于接口或交易测试通过。

## 1. 测试分层与环境

单元：金额、步长、权益去重、风险方向、窗口计算、幂等和状态机。契约：标准 Adapter、HTTP / WS Schema 与前端类型。回放：脱敏官方样例和本地 fixture。集成：真实数据库 / Redis、迁移、outbox与进程恢复。端到端：浏览器操作、权限、重连和可见错误。负载：按 PRD 基准分开测上游、后端与浏览器延迟。

所有层优先不依赖实盘。外部私有只读测试需对应凭据和明确权限；Demo 下单与真实下单分别授权。任何文档生成或 CI 默认不得发送真实交易、转账、提现或外部消息。通知测试使用可控 fake provider。

## 3. 接入测试矩阵

每个支持组合建立记录：exchange、region、environment、account_mode、market_type、position_mode、margin_mode、sdk_version、doc_date、case_id、status、evidence_path、operator、executed_at。

- Binance：Spot、USDⓈ-M；现货新签名订阅、Futures public / market / private 路由；普通与条件单分别测。
- Bitget：经典 / UTA；v2 / v3、Demo 与生产只读、WS 时间戳、盘口版本和 liquidation 量纲分别测。
- OKX：地区域名、交易 / 资金账户、净额 / 双向、合约张数与条件单分别测。
- 状态只能为 PASS、FAIL、NOT_RUN、UNSUPPORTED；能力未测不等于失败，也不等于可上线。

## 4. 故障注入的最低范围

延迟 / 乱序 / 重复外部事件；订阅 ACK 后没有首帧；连接提前关闭；429 / 业务限流；系统时钟偏移；数据库事务失败；outbox重复分发；Redis 重启；行情 worker、账户 worker、执行 worker 进程崩溃；实例交接时旧进程仍存活；第三方通知部分成功；前端切换账户与断网重连。

关键不变量：已持久化命令可找回；已确认成交不重复；未知订单不自动制造第二单；丢失领导权不继续提交；保证金 / 预算超限不因并发绕过；数据缺失不变零；页面不会把部分完成任务显示为成功。

## 5. 发布检查

V0.1：三所只读范围明确、密钥加密、脱敏、资产去重、账户对账、过期提示、告警和备份恢复完成。V0.2：另需交易模式矩阵、条件单、幂等、紧急退出、未知订单和安全专项审查。V0.3：另需插件隔离、预算、日志、归因与重启恢复。

上线前核对官方变更日志和来源登记表全部阻断项；账号 / 地区不支持的能力从 UI 和后端同时禁用。实盘开关只有在实际证据齐备且用户明确授权后开放，本次文档交付不改变该开关。

## 6. 证据与测试报告

每次测试留存：版本 / 提交、环境、输入fixture、脱敏请求摘要、预期结果、实际结果、日志关联ID及截图或机器报告。fixture不得包含真实密钥、签名、Cookie或个人财务明细。报告缺凭据 / 网络 / 功能未实现时填 NOT_RUN；本轮只对文档链接、需求覆盖和一致性做静态检查，不执行功能构建、交易所联调或真实通知。
