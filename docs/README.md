## 基线决策

- 项目名 TradeOrbit，仓库 E:/github_repo/TradeOrbit；现有四个开源仓库只作参考和依赖评估。
- 首期面向个人或可信小团队自部署；角色为管理员、交易员、观察者。不是公开托管资金的 SaaS。
- 前后端分离、同仓维护；Vue 3 + TypeScript + Vite + Pinia；Python 3.12+ + FastAPI + asyncio；PostgreSQL + Redis；Docker Compose。
- 首期市场范围：现货与 USDT 结算线性永续；账户资产覆盖范围必须显式显示。币本位、交割合约、期权、借贷、理财资产纳入后续独立适配。
- 产品路线仍按只读资产 / 行情 / 预警 → 手动交易与 TWAP → 隔离策略推进。工程发行版本 0.2.0 当前包括 E02-M1 和 M2.1，只读阶段仍未完整验收，不代表交易阶段已开放。
- 三所必须区分账户模式、环境、市场和产品能力，不能以一个 enable_trading 布尔值代替全部检查。
- 金额和数量通过字符串传输、Decimal 运算；未知或缺失数据不能显示为 0。
- 实盘配置默认关闭；文档和测试均不授权真实下单、转账、提现或向外部渠道发送消息。

## 变更规则

每项需求用 FR-模块-编号标识；修改时同时检查工作包、接口、数据库和验收用例。未确认事项集中列在来源登记表，不能把“待验证”当成“支持”。任何交易写接口必须等 E04 的风控和对账验收完成后开放。

本套文档覆盖完整产品路线图；当前实现 E01 的认证、账户配置、加密、审计和基础设施，以及 E02-M1 的公开行情、自选与详情快照、M2.1 的手动账户余额/持仓快照；私有持续同步、聚合 NAV、完整增量盘口与交易仍为后续设计。总体规范核对截至 2026-10-30，公开行情路由在 2026-10-31 做过真实探测，私有路由同日做文档/源码核对及回放测试，真实私有账户联调 NOT_RUN；上线前按账户所在地区、产品权限和当日变更日志重新确认。
