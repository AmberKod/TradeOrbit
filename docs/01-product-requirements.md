# TradeOrbit 功能需求文档

版本：v0.1 / 日期：2026-10-30 / 状态：规划基线 / 输入：用户已确认的五类核心模块及多交易所需求。

## 1. 产品目标与使用范围

在一个网页内查看 Binance、Bitget、OKX 的资产、持仓和行情，发现异常后获得可追溯告警，并通过统一执行入口完成手动或策略交易。优先解决“资产看不全、风险发现晚、跨所操作割裂、策略状态不透明”。

用户角色：管理员配置账户、密钥、通知与权限；交易员查看并操作获授权账户；观察者只读。首期默认一个工作空间，但数据表保留 workspace_id 边界。普通交易员不能读取交易所 Secret 或修改权限。

首期资产包含已接入账户域中的现货和 USDT 线性永续权益。未接入资金账户、理财、借贷、币本位等资产必须显示“范围未覆盖”，不得把部分资产称为全交易所总资产。资金账户查询可按连接器能力启用，只读，不提供自动划转和提现。

### 版本与边界

| 版本 | 目标 | 发布条件 |
|---|---|---|
| V0.1 | 资产、持仓、行情、预警、通知与连接健康 | 三所只读链路、数据过期识别、断线恢复、资产对账可验证 |
| V0.2 | 统一手动交易、平仓、反向任务、TWAP | 订单幂等、状态未知处理、账户风控和模拟环境故障验收通过 |
| V0.3 | 策略插件、运行管理、日志、回放和收益归因 | 进程隔离、权限、重启恢复和策略对账通过 |

跨所自动套利、开放式代码上传、多租户计费、跟单、资金托管、高频撮合和无监督马丁策略不是首版交付范围。接口支持后可另立需求，不能在当前工作包中暗增。

## 2. 信息架构与核心流程

页面：资产总览、持仓中心、行情工作台、交易工作台、策略中心、告警中心、系统设置。

核心只读流程：添加账户 → 验证只读能力 → 识别账户模式与覆盖范围 → 建立私有流并完成初始对账 → 展示净值与持仓 → 配置预警 → 查看触发与发送记录。

核心交易流程：选择账户 / 市场 / 标的 → 展示可用能力及精度 → 填写委托 → 预检 → 提交幂等命令 → 显示交易所受理与成交状态 → 对账。HTTP 成功不能显示为成交成功。

核心策略流程：选择已审核插件 → 绑定账户与预算 → 模拟运行 → 校验参数 → 启动实例 → 监控订单 / 日志 / 敞口 → 暂停或按明确退出动作停止。

## 4. 业务计算口径

### 资产与收益

NAV = 已去重账户域权益按有效估值价格折算后的合计；总权益已经包含持仓未实现盈亏时，不得再加一次持仓 PNL。可用余额不是总权益，抵押折扣后的可用权益也不是资产市值。资产范围、估值时点、缺失账户和未定价币种必须与数字一起返回。

收益先提供“期间资产变化”和“现金流调整后的损益”：期末 NAV - 期初 NAV - 外部净流入。外部流入含充提及与统计范围外账户的划转；统计范围内划转应配对消除。资金费和手续费属于收益组成，不作为外部入金。不同计价本位下，资金流按发生时点折算。

单位净值 / 时间加权收益只在资金流和边界估值足够完整时发布；否则提供带说明的估算或不提供。收益回撤基于经资金流处理的净值序列；原始资产曲线下降不能无条件标为投资亏损。

### 行情与风险

价格波动建议以滚动 60 秒价格变化定义；爆量使用同长度历史窗口成交量基线，并排除当前窗口，配置最小有效样本和最小基线。成交量按相同 quote notional 比较，不能把张数直接与币数比较。

资金费率保留结算周期、下次结算时间和原始符号；按统一周期比较时注明换算方法。费率差 / 买卖价差只代表候选信号，不能显示为保证收益。

合约持仓盈亏优先显示交易所标记价格口径；最新成交价另列。保证金率的危险方向按交易所和账户模式解释，不能把所有高百分比都当作安全或危险。红绿配色可配置，风险同时用文字和图标表达。

## 5. 非功能与质量目标

以下为设计目标，不是现有实测：基准负载定义为 3 所、6 个账户、100 个轻量关注标的、10 个深度标的、3 个浏览器会话。盘口优先使用普通公开档位，避免默认依赖 VIP。

- 网页内部推送在基准负载下以接收至展示 P95 ≤ 500ms 为初始目标；交易所事件至展示单独测量，不承诺上游毫秒级全量数据。
- 行情 / 私有流 freshness 分频道配置；时间阈值是产品配置，不能改写交易所实际推送周期。连接正常但无成交的市场不凭“没成交”判断断线。
- 数据断线、缺价和队列溢出必须可见；失效数据不得继续驱动新开仓。
- 关键订单与成交记录以数据库事务持久化，恢复测试要求已提交业务记录不因进程重启丢失。
- 高危快捷键默认未绑定；启用后需明确账户范围和操作含义，避免多个页面重复触发。
- 业务时间存 UTC，界面默认跟随用户时区；金额 / 数量均为 Decimal 字符串，不使用二进制浮点参与交易核算。

## 6. 代表性验收场景

1. Given 同一 OKX 交易账户同时有现货与永续，When 聚合 NAV，Then 共享权益仅计一次，持仓 PNL 仅作拆分展示。
2. Given 私有流中断，When 用户尝试新开仓，Then 后端返回 ACCOUNT_NOT_READY，页面展示恢复状态；退出操作走单独的降级规则。
3. Given 首次订单请求已到交易所但 HTTP 响应丢失，When 用户再次点击，Then 复用同一命令并查询订单，不创建第二笔逻辑委托。
4. Given 收到重复成交、乱序订单状态，When 重放事件，Then 成交不重复入账、累计成交量不回退。
5. Given 行情基线不足，When 配置爆量规则，Then 显示预热状态；不把小于正常基线的噪声放大成异常。
6. Given 紧急退出中部分账户失败，Then 任务展示部分完成及剩余敞口，不显示“全部清仓成功”。
7. Given 本期 NAV 因入金增加，Then 资产曲线上升但该入金不被计为交易收益。
8. Given 通知服务返回受理但无送达回执，Then 状态为 PROVIDER_ACCEPTED，不能显示“用户已收到”。
